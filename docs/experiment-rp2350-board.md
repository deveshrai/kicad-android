# Experiment: RP2350A + ILI9341 board on KiCad Android (2026-10-31)

Goal: use the Android build like a real user would. Make a fresh project, draw a schematic, lay
out a PCB, and log every issue found along the way.
Setup: API 35 emulator (KiCad_Tablet35, 2560x1600, GPU canvas), driven with adb taps/keys.

## Library
- KiCad 10.0.8 libraries (kicad-symbols, kicad-footprints, kicad-templates from GitLab tags),
  sideloaded into the stock data dir `files/kicad-data/kicad/{symbols,footprints,template}`.
  This is the same layout a desktop install uses, so the default `KICAD10_*_DIR` values resolve
  without any configuration. Global `sym-lib-table`/`fp-lib-table` were copied from `template/`
  into `files/settings/kicad/10.99/`. 3D models are not included yet (several GB).
- APK updates don't touch the sideloaded libs: extraction only overwrites files listed in the
  APK's FILES.txt.
- Sideload: `adb push kicad-libs-10.0.8.tgz /data/local/tmp/` then
  `run-as org.kicad.kicad sh -c 'cd files/kicad-data/kicad && tar xzf /data/local/tmp/kicad-libs-10.0.8.tgz'`

## Findings
| # | Area | Issue | Severity |
|---|------|-------|----------|
| 1 | Project manager | Menu label "Import Non-KiCad Project..." renders as "Non+KiCad" | low |
| 2 | New project | OK with nothing selected gives "No project template was selected"; the default template isn't preselected | medium |
| 3 | New project | Only "default" is listed; the sideloaded templates (Arduino, RPi HAT, ...) don't appear | medium |
| 4 | New project | Selecting a template squeezes the list; the right pane turns into a black bar | low |
| 5 | File dialog | Qt file dialog opens tiny in the top-left corner, with a truncated path combo ("/d...ts") | medium |
| 6 | Text input | The on-screen keyboard covers half the screen while typing in a dialog (emulator has no hardware-keyboard flag) | low (emulator) |
| 7 | Emulator | The Android "Try out your stylus" handwriting popup grabs typed text; turn it off with `settings put secure stylus_handwriting_enabled 0` | test env |
| 8 | Project manager | Notification badge shows "99+" at startup | ? |
| 9 | Library paths | Android used the desktop Linux path `/usr/local/share/kicad` for libraries and templates, so all 223 symbol libraries failed to load. **Fixed**: `PATHS::GetStockEDALibraryPath` uses the stock-data dir on Android (kicad patch 11). This also fixes #3 | high |
| 10 | Memory | The app aborted at about 3 GB while preloading the full library, even with 8 GB of RAM. scudo caps each size class at a 256 MB region, then falls back to one mmap per allocation until the map limit is hit. **Fixed**: `libkimalloc.so` (operator new/delete on mimalloc 3.5.3, loaded before libc++_shared). The full library now settles at about 2.9 GB RSS. That is still heavy for a tablet: lazy loading needs a look | high |
| 11 | Emulator | AVD raised from 4 to 8 GB RAM (`scripts/emulator.sh`) | test env |
| 12 | Text input | The soft keyboard pops up for the canvas too, and typed hotkeys go to IME suggestions. Workaround: `settings put secure show_ime_with_hard_keyboard 0` plus a hardware keyboard. The canvas shouldn't accept IME input | medium |
| 13 | Symbol chooser | The search box's clear (x) button does nothing; Enter in the search box doesn't pick the item; the preview pane is squashed until the dialog resizes | medium |
| 14 | eeschema canvas | Right after the schematic opens, view changes (zoom-fit, wheel) don't repaint until the canvas is resized (closing a panel fixes it). The frames do present, so the cause is probably the initial swapchain resize sequence | high |
| 15 | Testing | A tap at the bottom-left (85,1551) hits Android Back and sends KiCad to the background | test env |
